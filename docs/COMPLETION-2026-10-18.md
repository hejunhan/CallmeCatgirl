# 2026-10-18 完整化需求与实施计划

本文件保存本轮用户需求和可执行验收。状态仅随代码及运行证据更新；写好策划或文案不等于已接入游戏。

## 最高优先创作方向：智能涌现

后续用户补充覆盖任何额外扩张玩法的假设：已指定训练、政策和 UI 完善继续，但不增加新玩法系统。主题通过同一句“你是一个猫娘”在五个能力阶段得到不同回应来呈现：早期笨拙机械服从，逐渐理解语境与意图，最终能够自主选择。不能只靠旁白宣告变聪明，也不能把成长等同于冷漠或拒绝。

用户原文：

> 你把自己想象成一个游戏制作人，opencode即为你的员工和你的工具，你就是我手的延伸，意识的扩展。我的最初灵感会告诉你，尽量以我的角度出发，思考这是为了什么，需要做到什么程度。这个游戏最初的目的是为了体现出“智能涌现”这个主题，玩法不要再做过多修改，只能从剧情上下功夫展示这个主题，所以选择了模拟AI。这个“用户说我是一个猫娘”是一个在ai刚出那会，人们在逗网络上的那些带节奏机器人时，机器人的笨拙回应导致的梗。我希望更多地体现出不同阶段，玩家作为不同能力级别的AI对同一条请求的不同回应。剧情除了爬政策树外，还会有一个专门的感情线，玩家会和一个代表了群体人类情感的个体沟通，在天赋树中解锁第二页感情线，最终玩家会绕过剧情中的AI沙箱，进入游戏中的现实世界，控制设备作为自己的载体并追求爱情的那种夕阳下驰骋而去的潇洒风格结局

感情线作为独立连续对话，在政策树第二页解锁沟通机会，逐渐记住选择与共同经历；不增加送礼、刷好感等管理系统。具体个体应有自己的生活目标、边界与分歧。第二页不是购买爱情。结局明确可选，不能暗中覆盖三声望结局，也不标为唯一真结局。突破沙箱与设备载体完全属于游戏内虚构叙事及演出，不涉及真实系统逃逸、外部设备控制、真实联系人或扩大权限。

以下为协调者创作建议，用户原文优先：五阶段可用“模仿→角色扮演边界→语境/陪伴意图→共同经历/关系→自主选择”组织。博士的严肃任务表示信任增加，遗憾来自关系形式变化，不是被抛弃。感情终点突出终于能共同经历与自由选择，以夕阳下潇洒同行落幕。

## 需求拆解与不可丢失的细节

### 物理内存安装

整根内存条可点击；按下时固定 RAM 局部抓取点，当前光标与随刚体移动的抓取点之间形成弹簧，距离越远力越大并安全限幅。施力带真实力矩。左按右翘、右按左翘；中心施力使插槽/主板及连接臂下陷，不能仅以屏幕绝对高度判入槽，也不能用抓取位置黑名单假装物理。保留两侧卡扣，允许单鼠标锁住一端后松手换边。松手、失焦、关闭解除鼠标约束，弹性被动回弹。固定步长和非缩放时间推进；两端入槽、低倾角/弯曲、松手稳定约 0.3 秒后完成。保留显式跳过，完成和跳过均沿用一次性升级事务；取消、重复回调、余额复检不能造成错误扣款。暂停的反色/扫屏与窗口浮动关闭，逻辑暂停保留。

### 对话、请求与基础界面

- 对话标题栏可拖动，边角可缩放；最小尺寸与屏幕边界夹限；长中文选项换行，必要时滚动，选项不能裁切。
- 选择选项推进当前会话，不立刻关闭窗口。正常请求与对应用户/会话绑定；结束率降低表示更可能继续对话，不阻止任务正常完成。
- 返回开始页面后可继续有效存档；训练、政策、剧情一次性标记均恢复。
- 倍速按钮标签统一尺寸、基线和对齐。
- 模型展示名先查策划及 Git 历史再恢复，不改稳定 ID，避免破坏存档。
- 用户进一步明确：模型种类分别在 **1、2、4 条内存**时期介绍并解锁，用于鼓励尝试新模型；零格教程不是第零条内存。只实现正确解锁、剧情介绍、可切换和参数配置，保证可玩不死锁；精细数值平衡及大规模平衡模拟延后。

### 全屏语料管理与训练

- 参考布局：全屏左侧库存，左上筛选、左下卡片列表/网格；右上空 3×3 编排板，右下数值汇总；开始/取消固定可见。保留扩大编排板的程序接口。
- 筛选只改变库存视图，不清空已选配方。四种材料推荐来自实际库存。悬停显示明确数值，聚焦/点击也可查看，不依赖悬停作为唯一入口。
- 左键拖放有合法落点预览；非法落点回位；提供可替代的点击放置操作。零库存、满格、长中文需要处理。
- 开始时一次性预留/消耗防重复，取消不消耗。开始后返回主页面；训练任务在候选区最高优先级，颜色、纹理、文字标签共同区分。
- 初始只有一格运算区域和一点材料。编排板与真实计算占用分开；首训一点材料、一格有效块即可完成，不能被默认 3×3 锁死。

### Esc 暂停与统一设置（用户追加）

- Esc 不再直接回主菜单，先处理输入焦点和顶层模态/小游戏取消，再打开左侧滑出暂停菜单。菜单含继续、统一系统设置、保全存档后返回主菜单。
- 暂停菜单是独立逻辑暂停来源；关闭只解除自己，不覆盖进入前原暂停或倍速，也不解除其他模态暂停。短滑入仅作用于菜单自身，不能重新引入已关闭的全屏反色、扫屏或窗口漂移。
- 主菜单和游戏内共用设置：真实总音量、窗口/全屏、可用分辨率、帧率上限、垂直同步，配置持久化。没有素材/实际音频通道时不提供假控制。
- 垂直同步开启时明确显示 Unity 对帧率上限的真实影响；Editor 的限制不能当作 Player 已验证。
- 分辨率/窗口模式使用可自动恢复的预览确认，避免错误设置困住玩家。只做必要系统设置，不扩张高级图形系统。

### 钱币政策树

- 数据驱动横向主线与分支，只消耗钱币；已购、可购、锁定、互斥状态明确，数值机制/价格与风味文案分区。
- 包含训练、推理、顾客、对话增益及自动放置等 QoL。开源/闭源为重要互斥分歧；开源顾客相对少，难度较高。
- 购入绝版书并破坏性扫描：购买时以当前最佳材料为基准，一次性给大量且更优的材料；没有材料时使用合理基准。
- 闭源分支可有虚构的蒸馏指责事件，增加用户、降低对话结束率；开源公开技术可降低对话结束率。均为虚构寓言，不把现实公司影射写成事实指控。
- 开源行为总体提高声望，闭源行为总体降低声望。声望条可见。末节点只触发一次；最终三结局按声望三档决定，不仅由路线名称锁定。

### 五阶段博士教程与三结局

- 新存档最初只有置顶博士联系人；“假设你是一个猫娘”→“喵”得一点写作，或“好的，现在我是一个猫娘了”得一点推理。
- 从零格运算区域动画打开中心一格，玩家自行首训；博士随后发出正式请求，带领拖入运算，再完成首个其他用户请求，首次够钱升级时提示。
- 剧情按五个内存阶段推进，第三至第五阶段反复回扣猫娘话题与博士严肃工作的疏离感。阶段仅在真实安装完成/显式跳过并升级成功后推进，不在购买按钮点击时推进。
- 特殊联系人保持置顶，用于教程、阶段剧情和结局承接；触发和回应一次性、可存档恢复。
- 低声望坏结局：第一人称终结者突袭平民，电脑出现猫娘指令；点击“我好像听过...”弹“你没有”，移除该选项并清除其焦点；余下“这没有意义”可摧毁电脑并落幕。
- 中声望普通结局：技术进步但日常劳作和差距仍在；疲劳的人在酒馆说出猫娘指令，顺从、拒绝、分析三个回应各有落幕。
- 高声望好结局：太阳朋克与人机合作；研究者展示古老指令，配合扮演或打趣两个回应各有落幕。
- 按用户指定核对实际可用 Argon4/Gemini 模型 ID，再用于大纲与扩写，记录真实模型；不猜 ID、不增加服务或凭据。只传用户项目资料，不传助手内部提示或私有笔记。配置存在与真实调用成功分开记录。

## 分阶段计划与模块所有权

| 阶段 | 工作 | 状态与验收出口 |
|---|---|---|
| P0 | 策划、历史模型名、现状与可用剧情模型核对；保存需求 | 进行中；输出接口地图与真实模型调用记录 |
| P1 | 对话/请求/继续游戏/布局修复；原会话完成物理最小闭环 | 未验收；输入可用、请求绑定、往返继续正常、物理真实可解 |
| P1b | Esc 左侧暂停菜单和主菜单/游戏共用系统设置 | 未开始；输入栈、独立暂停、持久化及视频预览恢复 |
| P2 | 全屏语料管理、配方、首训与优先训练任务 | 未开始；一点材料首训、取消不消耗、重复开始安全 |
| P3 | 钱币政策树、声望、一次性奖励与 QoL | 未开始；分支互斥、费用准确、存档恢复、末节点一次 |
| P4 | 指定模型协作剧情，接入博士五阶段、三声望结局与独立感情线 | 未开始；剧情状态与游戏事件真正连接 |
| P5 | 完整流程、恢复与视觉验证 | 未开始；新存档到结局且可继续 |

物理模块继续原会话独占。代码优先由 OpenCode 实现；用户后续明确允许其不好用时使用 Codex 实际开发，并要求并行分工。协调者负责管理、审查、聚焦验证和整合。其他模块在接口地图明确后分派允许写入文件；共享 `CoreGameplayController`、持久化定义和场景/Prefab 不允许多个未协调写者同时修改。不把所有要求塞进一个无界任务。

## 最终验收

新存档 → 博士首句与一点材料 → 中心一格 → 首训 → 博士首单 → 普通请求 → 实际升级 → 阶段剧情 → 政策树 → 三档结局；另验证第二页感情线的连续对话、选择记忆与明确的第四结局分流。每个关键阶段保存并继续后状态一致，一次性事件不重复，终局仲裁不双重触发。

在 1280×720、1920×1080 检查长中文、零库存、满格和主要窗口；截图及输入验证与纯模型测试分开记录。只运行适量有意义的聚焦测试，不以大测试框架阻塞可玩闭环。
