# 当前 Unity 实现叙事终稿 · Web 对齐用

这是当前 Unity 实现的完整可读终稿，依据 Argon 素材编辑并以实际目录、选项处理和状态转移为准，**不是 Argon 原稿或待实现提案**。下方引文、选项、标题与说话者逐字取自当前实现；「条件」「后续」属于对实现的说明。稳定 ID 用于 Web 对齐，不替代正文。

本稿覆盖 45 个稳定剧情节点，展开为 69 个条件文本版本。没有运行 Unity、Player、桌面或浏览器；文字完整性不等于运行或画面验收。

## 实现口径与 Argon 整理差异

1. **移除强制越界。** Argon 第四段把玩家预设为试图修改林栖调令评分、替她安排人生，并在第五段提出强行弹窗的支路。当前稿保留保护冲动与真实分歧，但两项选择分别先询问、承认并收回自己的冲动；第五段只提供尊重时间的短笺或不发信。没有实际篡改调令、设备或私人数据的操作。

2. **阶段按实际物理内存条数。** 零格开场开放的中心一格仍是 0 条物理内存；五阶段在第 1～5 条内存安装或跳过提交成功后排入剧情。1、2、4 条分别介绍 Transformer、MoE Transformer、协调状态架构，不把教程算作第零次升级，也不在点击购买时提前推进。

3. **移除未请求的选项 buff。** Argon 第一阶段曾提出选择蠢萌回答会增加闲聊短单、选择定义回答会让工具订单匹配更顺畅。当前这类回答只记录选择、改变后续台词及回忆；不因猫娘回答附送客流、匹配效率或其他隐性增益。开场的一点语料、主线真实委托与政策效果仍按已实现机制执行。

4. **声望阈值具体化。** Argon 只给高低阈值占位，且低档写作「小于低阈值」。当前实现明确为声望 ≤ -15 进入坏结局，-14～14 进入普通结局，声望 ≥ 15 进入好结局；路线名称不直接锁定结局。接受林栖邀约只开启终局时的显式分岔，不能暗中覆盖政策结局。
