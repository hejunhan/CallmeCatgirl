# 美术指导

**本项目以复刻《明日方舟》常驻 UI 的视觉语言为目标。瑞士风格是分析工具，不是覆盖参考的目标。**

本文用于主界面、游戏内 IM 浮窗和任务交付窗口。用户已确认的结构与动效优先保留；可读性和分辨率验收继续遵守 [UI 规则](UI-RULES.md)。

## 参考与适用范围

主要视觉依据是 [Yostar 官方 App Store 页面](https://apps.apple.com/id/app/arknights/id1464872022?platform=ipad)中的主界面、作战终端、战斗 HUD 和基建画面。可直接对照[主界面截图](https://is1-ssl.mzstatic.com/image/thumb/PurpleSource211/v4/36/5d/2b/365d2b4b-350c-e2f7-e0be-d1c8ddd11457/2732-x-2048-1.jpg/1286x964bb.webp)与[基建截图](https://is1-ssl.mzstatic.com/image/thumb/PurpleSource221/v4/a9/88/18/a98818cc-ee29-49e8-8443-0e9fc915fcfc/2732-x-2048-4.jpg/1286x964bb.webp)。这些是含游戏画面的营销图，只参考内部游戏 UI，不搬用外部荧光黄边或宣传包装。

从参考画面归纳的方向是：用白色实心功能块、深浅透明块和非对称分布组织信息，以大字、关键数字和块面建立重量，细线辅助表达关系。下文的四层字体和描边取值是本项目对观察结果的转译，不是官方设计标准。

瑞士风格帮助分析对齐、比例、排版网格和克制用色；网格是对齐关系，不等于满屏格线。其历史依据见[瑞士国家图书馆：国际风格，1950—1970](https://www.nb.admin.ch/en/the-international-style-1950-1970)。功能主义极简帮助删去无用表达，不删状态反馈；参考[设计博物馆：Dieter Rams](https://designmuseum.org/designers/dieter-rams)，不将 Rams 等同于整个极简主义流派。两者都不能成为把方舟参考简化成全套细线框的理由。黑白灰仍是本项目选择，不是瑞士风格的唯一形式。

## 构图与块面

- 中央运算区占最大面积，成为主焦点；左侧保留常驻会话栏。用非对称布局平衡视觉重量，不为左右等宽牺牲主要内容。
- 用白色实心功能块和深浅透明块区分入口、内容与背景。字与面承担主要重量，不给所有元素套同粗细的空心框。
- 各面板共用少量对齐轴，按 8 的间距节奏组织内容。用比例、留白和距离表达分组，线只补充说明关系。
- IM 保持清晰的窗口边界：顶部标题栏与右上窗口控制，消息区左右头像和气泡，底部动态回复选项卡。会话与任务交付复用同一窗口结构，不因追求少画线而丢掉必要边界。
- 气泡、回复卡和窗口外壳各有用途，不再叠多圈装饰框。用户候选元素只保留指定形状，不额外添加编号或标签。

## 四层字体与中英结构

| 层级 | 用途 | 执行方式 |
| --- | --- | --- |
| 大标题 | 当前页面或主要功能区 | 用面积、字号和真实字重建立主次，不给每个小块都加大标题 |
| 关键数字 | 核心数值和进度 | 清楚突出，与对应单位和标签对齐 |
| 正文 | 中文说明、操作与对话 | 优先保证理解、完整和可读 |
| 小辅助标签 | 短英文栏目、单位、真实编号或时间 | 辅助结构节奏，不压过主要中文信息 |

- 使用项目现有 HarmonyOS Sans 和真实字重，不猜测或声称它是方舟官方同款字体。正文以 Regular 为主，标题与操作可用 Medium/Bold，不用软件伪粗体。
- 中文承担主要理解；`CHAT`、`COMPUTE` 等短英文栏目可服务结构和节奏。真实编号和时间有用途时可用，不一律删除英文或装饰。
- 删除 AI 解释空话、无意义英文、假日志和伪终端编号。候选形状不因此增加标签；标题若用英文，也不恢复已删除的左上总标题。
- 以左对齐为主，共用实际文字基线和行高。按渲染字身校准，不仅比较文字容器的位置。同层字号、字重和间距一致。
- 不用细小、低对比文字制造精致感。容器不足时换行、扩容或滚动，不缩字硬塞。
- 大字裁切仅是可选的项目手段，不声称是方舟界面的共性。若以后采用，只放在背景层，不裁必要信息；当前不强加。

## 描边与状态条

以下是项目起始建议，需按实际画面调整，不是方舟官方数值。px 指最终屏幕实际像素，不是 Unity 单位。

- 1 px 用于辅助分隔或弱关系；2 px 内描边用于重要边界或选中候选；4～6 px 的短状态条可表达明确状态。层级由用途决定，不把所有线画成相同粗细。
- 候选元素保持内描边。状态变化只向内部增厚，外轮廓占用、布局尺寸和命中区域保持不变，禁止外扩多圈形成贴纸式粗边。
- 内部分隔线弱于必要外边界，共享边只画一次。线用于分组、边界或状态，不画满屏等粗格线。
- IM 外边界、左右气泡和回复选项卡要清楚可辨。描边与块面共同建立层级，不以发光代替边界。

## 颜色与动效

- 黑白灰构成底色和主要信息；深浅透明块按最终合成画面检查。有限强调色服务真实状态，并配合文字、符号或形状，不能只靠颜色识别。
- [UI 规则](UI-RULES.md)中的文字对比至少 4.5:1、必要边界与状态至少 3:1 继续有效。HSV 仅辅助稳态调色，不能代替亮度对比验收。
- 保留右侧固定、左侧漂浮旋转、暂停时 45° 扫动与 0.7 秒悬停。不泛化成随机斜切或全界面持续运动。
- 一次反馈优先使用一种清楚的变化，不同时叠加放大、加粗、发光、跳动和反色。发光仅辅助反馈，不压文字，也不承担唯一选中标记。

## 执行取舍

| 应做 | 避免 |
| --- | --- |
| 用主次块面、比例和大字建立重量 | 所有区域等重，全套细线空心框 |
| 用对齐和留白组织信息 | 满屏等粗格线、无用途角标和多圈外框 |
| 中文讲清用途，短英文提供栏目节奏 | 误删所有英文，或补写假日志、空话和候选编号 |
| 真实编号、时间与状态各司其职 | 把每个空位都填成装饰信息 |
| 保持已确认的动效，反馈解释操作结果 | 全部发光、持续跳动或堆叠多种反馈 |

## 五项验收

1. 主次块面清楚，中央运算区是主焦点；白色功能块与深浅透明块有明确分工。
2. 大标题、关键数字、正文和小辅助标签形成四层字体，同层排版一致，无缺字或溢出。
3. 中文能独立讲清操作，短英文服务栏目结构；没有假日志、候选新增编号或被恢复的左上总标题。
4. 候选普通与选中状态外轮廓重合，布局和命中区域稳定；IM 边界、左右气泡与回复选项卡清楚。
5. 去掉发光后，块面、文字和状态仍有清晰层级；去掉强调色后仍能识别必要状态。每条线和每个动效都能说明用途。
