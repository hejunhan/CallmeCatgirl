# 对话弹窗与剧情配置

主场景：`Assets/_Game/Scenes/Prototypes/CoreGameplay.unity`。

主配置 `CoreGameplayConfiguration.asset` 的“剧情配置”引用 `StoryConfiguration.asset`。选中后直接在 Inspector 修改内容；修改后重新运行或重开验证。原内存配置已保留。

## 提交流程

1. 请求算完后点击“提交”：立即释放格子，并按原规则结算一次。
2. 自动打开该用户的独立对话弹窗，显示开局记录、历次请求、提交质量、玩家回复和用户回应。
3. 选择一个回复，记录双方发言并保存下一段剧情。弹窗关闭，时间恢复原来的运行或暂停状态。没有选择前无法关闭回复弹窗。
4. 点击原有“下一轮”，创建该选项指定的任务。下一次提交时进入指定的剧情段落。

阅读期间游戏时间、任务进度、忍耐期限和月度维护计时全部冻结。不会改变玩家原本的暂停设置；重复提交不会重复结算。一次处理多个提交时，弹窗逐个显示。超时不属于主动提交，不弹回复选项。

右侧通讯栏显示简短摘要，“查看过往对话”打开同一弹窗供回看，这时可以点击“返回”。

## 剧情字段

| 字段 | 填写方式 |
|---|---|
| 用户ID | 当前三个用户为 A / B / C，与主配置请求ID对应；同一用户后续可以切换任务类型 |
| 显示姓名 | 林小满等自定义姓名 |
| 开局对话记录 | 多行文字，可自行写角色名字和对白 |
| 首段剧情ID | 第一次提交进入的段落，例如 start |
| 剧情段落 / Id | 同一用户内唯一，供选项跳转引用 |
| 提交后用户发言 | 此段进入时自动追加的用户对白 |
| 按钮文字 | 玩家看到的选择，例如“温柔地说晚安” |
| 玩家回复 / 用户回应 | 选择后分别追加到对话记录，留空则不追加 |
| 质量条件 | Any 任意质量 / CompleteOrBetter 完成及以上 / ExcellentOnly 仅优秀；不满足的选项隐藏 |
| 下一次提交的剧情ID | 下一次主动提交进入的段落；留空结束当前剧情，之后使用默认选项 |
| 下一轮任务ID | 使用主配置 Requests 中的 Id，例如 A / B / C；留空沿用刚提交的任务类型 |
| 默认回复选项 | 未配置角色或剧情已结束时使用；配置漏填或选项全被质量条件挡住，自动提供“发送回复”，避免卡住 |

配置的用户/段落ID必须唯一，剧情跳转和任务ID必须存在；开局会检查并在 Console 报出具体配置错误。默认回复选项建议不填写段落跳转，只用于通用回应。

## 已配示例

林小满的 start：选择“温柔地说晚安” → warm 段、下一轮任务 A；选择“先聊聊今天的烦恼” → plan 段、下一轮任务 C。第三个特别晚安信选项要求优秀质量。周序与苏禾也各有两段示例，可直接替换为正式剧情。

## UI 与代码

`GameplayCanvas/ConversationPopup/Window` 已保存为真实 uGUI 场景对象。UserAvatar、UserName、Result、HistoryScroll、ChoiceScroll 和 CloseHistory 都能直接编辑。ChoiceTemplate 是隐藏的按钮样板，运行时只按配置复制选项，不重建整套界面；选项和历史均可滚动。

`StoryConfiguration` 保存策划数据；`ConversationStory` 管理各用户的历史、段落和待回复队列；`ConversationPopupView` 显示弹窗；原控制器通过任务事件连接剧情。没有增加剧情第三方插件。

当前历史与分支进度只保存在本次运行的内存中，重开恢复配置里的开局记录，尚未接入磁盘存档。弹窗不会生成真实 AI 文本，对白完全来自配置。选择后的“用户回应”会留在记录和右侧摘要中，也可再次打开记录查看。
