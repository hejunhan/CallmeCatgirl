# 内存等级与新任务随机倍率

配置位置：Assets/_Game/Data/TaskGrid/MemoryUpgradeConfiguration.asset。

- 初始等级的新任务倍率：开局任务使用；默认计算量、奖励均1倍。
- Levels -> 升级后新任务倍率：每个等级分别设置计算量最小/最大倍率、奖励最小/最大倍率。都是相对原始任务的总倍率，不逐级累乘。
- 每个新任务生成时抽取一个0到1的随机权重，同时映射到计算量与奖励范围。因此同一等级内，更大的计算量对应更高奖励；上下限相同可固定倍率。
- 原始值先取剧情会话配置，没有则取Requests模板，再乘内存等级倍率。剧情自定义数值也会乘倍率。
- 倍率用于开局、月份刷新、手动新增及下一次剧情会话；已生成的候选、运算中及待提交任务都不重新抽样或涨数值。移动、旋转、撤回、重新放置不会重抽。
- 下一会话使用保存的未放大原始值作为兜底，不会用上一会话已乘倍率的数值继续叠乘。
- 只修改Calculation与Tokens：速度、忍耐、能力门槛、形状和原经济结算规则保持不变。实际资金=倍率后的Token收入乘单价，并按原规则取整；未达标仍为0，超时仍按完成比例结算。
- 任务卡和详情显示生成后的计算量与Token奖励；升级弹窗显示下一档倍率范围。更长任务也会占用内存更久，且可积累更多周期能力，具体数值可继续调。
- 随机种子继续使用TaskGenerationConfiguration.RandomSeed；固定种子方便复现。1倍兼容旧配置且不消耗额外随机序列。

| 内存等级 | 计算量倍率 | 奖励倍率 |
| --- | --- | --- |
| 1 | 1 | 1 |
| 2 | 1.1～1.3 | 1.4～1.8 |
| 3 | 1.4～1.7 | 2～2.6 |
| 4 | 1.8～2.2 | 3～4 |
| 5 | 2.4～3 | 4.5～6 |

例如原任务计算量100、奖励100Token，2级抽到中间权重时，会生成计算量约120、奖励约160Token的任务。若单价为1且达标，结算收入约160。

计算量倍率必须为正数，奖励倍率可为0，上限不能小于下限，NaN/无限值无效。初始读取时检查全部档位；运行中下一档配置无效时禁用升级，并在扣费/开格之前拒绝升级。
