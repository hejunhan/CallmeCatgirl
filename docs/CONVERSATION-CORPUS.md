# 对话语料与训练配置

## 现在的流程

1. 请求计算达标后提交，继续完成本次请求的所有对白。
2. 最后一轮结束才发放一次语料，归入该用户的对话。中途关闭窗口、重复点击、读档不会重复领取；不达标和超时不给语料。
3. 语料奖励 = 本次任务所有能力的**最高达标要求 × 0.5**，归入对应能力。例如写作10、代码2、推理2，基础语料为5点写作，学习型实际获得8点。使用任务要求值，不是实际产出或优秀门槛；再乘请求首次落位锁定的架构语料倍率（学习型1.6、高速型1、均衡型1.25）。奇数要求保留小数；最高值并列按能力枚举顺序取一项，避免重复发奖。没有正数能力要求不发放。
4. 打开模型广场，切到“语料与训练”。左侧每张卡片代表一位用户的整段对话，显示可用与累计点数。
5. 将卡片上的“拖入训练 / 选择”按钮拖到右侧投入区域，也可直接点击。移动滑条选择本次投入量，预览能力与形状。
6. 确认生成训练模块后才扣钱、扣对应点数。剩余语料保留。训练模块仍需要放入主棋盘才能运行，不可跨隔板。

## 策划配置

`Assets/_Game/Data/Training/DialogueCorpusTunableFallback.asset`

- **按最高能力要求发放语料**：默认开启。
- **最高达标要求的语料比例**：默认0.5。
- 关闭上述开关后，才使用原有的对白侧表/备用分数规则。
- 修改配置只影响后续奖励，已获得的语料不重新计算。

`Assets/_Game/Data/Training/TrainingDefaults.asset` → `Recipes`

- `Shape`：训练块基础形状，原数值保留，当前为6格。
- **每增加一格所需语料点**：默认2。额外格数 = 向下取整（投入点数 / 此值）。例如投入5点，基础6格，最终8格。
- **单次训练语料点上限**：默认20。
- `PointsPerScore`：每点投入转成多少模型能力，仍叠加已有训练策略倍率。
- 原有费用、计算量、能力产出间隔保持现有配置。投入量只影响语料能力和块大小，不额外放大费用/计算量。

增长保留基础格子，在基础形状宽度内逐行补相邻格，不能超过棋盘边界。预览显示完整形状，实际放置仍遵守开放格和隔板规则；放不下时可减少投入。

训练从该对话较早获得的语料开始扣除，同一条语料内按能力比例扣除。例如写作3、推理1，投入2点使用写作1.5、推理0.5。各能力不合并成一个能力值。

## 程序对接

- 新训练命令：`kind=train`，提供 `recipe`、`architecture`、`displayName`、`conversationId`、`corpusPoints`。
- `TrainingSession.GetConversationCorpus` 提供累计与剩余点数/各能力分数。
- `PreviewCorpus` 返回投入的原始能力构成；`PreviewTrainingAbilities` 包含配方和策略倍率。
- 原始语料记录不可变，训练作业保存实际扣除量；读档验证总扣除不超过来源总量。旧整条语料消耗存档继续按全额扣除解释。
- 固定投入区域和滑条保存于 `CoreGameplay` 场景的 `TrainingWorkspaceView` 下。通过场景对象调整位置，不在运行时重建固定布局。
