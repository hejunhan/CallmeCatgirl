# 对话语料与训练配置

## 现在的流程

1. 请求计算达标后提交，继续完成本次请求的所有对白。
2. 最后一轮结束才发放一次语料，归入该用户的对话。中途关闭窗口、重复点击、读档不会重复领取；不达标和超时不给语料。
3. 普通任务的每项能力都分别获得语料：**该项达标要求 × 独立随机比例（0.05～0.1）**，归入对应能力。例如写作10、代码2、推理2，基础语料分别为写作0.5～1点、代码0.1～0.2点、推理0.1～0.2点。使用任务要求值，不是实际产出或优秀门槛；再乘请求首次落位锁定的架构语料倍率（学习型1.6、高速型1、均衡型1.25），保留小数。剧情显式语料或精确对白侧表优先；没有正数能力要求时，仅在允许备用分数的配置下使用原备用规则。
4. 打开模型广场，切到“语料与训练”。左侧每张卡片代表一位用户的整段对话，显示可用与累计点数。
5. 将卡片上的“拖入训练 / 添加”按钮拖到右侧投入区域，也可直接点击。可连续添加多段对话；点击已添加卡切换编辑，滑条分别设置每段投入量，“移除此段”只移除当前段。预览整批能力、形状、计算量和预计游戏秒数。
6. 确认生成训练模块后才扣钱、扣对应点数。剩余语料保留。训练模块仍需要放入主棋盘才能运行，不可跨隔板。

## 策划配置

`Assets/_Game/Data/Training/DialogueCorpusTunableFallback.asset`

- **按最高能力要求发放语料（旧模式）**：默认关闭；开启后恢复只奖励最高要求对应能力的兼容行为。
- **旧模式语料比例**：默认0.1，仅在旧模式开启时使用。
- **每项能力要求的最低语料比例 / 最高语料比例**：默认0.05 / 0.1，每项能力独立抽取。
- 默认先使用剧情显式语料或精确对白侧表，没有配置时再按所有能力要求随机计算；无有效要求时按 `AllowRequirementFallback` 决定是否使用备用分数。
- 修改配置只影响后续奖励，已获得的语料不重新计算。

`Assets/_Game/Data/Training/TrainingDefaults.asset` → `Recipes`

- `Shape`：训练块基础形状，原数值保留，当前为6格。
- **每增加一格所需语料点**：默认2。额外格数 = 向下取整（投入点数 / 此值）。例如投入5点，基础6格，最终8格。
- **单次训练语料点上限**：默认100，按所有对话合计投入判断。
- `PointsPerScore`：每点投入转成多少模型能力，仍叠加已有训练策略倍率。
- 费用与能力产出间隔保留。总计算量 = `WorkTokens + WorkGrowthCoefficient × 总投入点数^WorkGrowthExponent`，再乘已有训练计算量政策倍率。默认值120、5、1.5；投入越多，训练时间超线性增长。详见 [多段对话合并训练](MULTI-CORPUS-TRAINING.md)。

增长保留基础格子，向周围相邻位置紧凑扩展，不能超过棋盘边界。预览显示完整形状，实际放置仍遵守开放格和隔板规则；放不下时可减少投入。

训练从该对话较早获得的语料开始扣除，同一条语料内按能力比例扣除。例如写作3、推理1，投入2点使用写作1.5、推理0.5。各能力不合并成一个能力值。

## 程序对接

- 多段训练命令：`kind=train`，提供 `recipe`、`architecture`、`displayName`、`investments: [{"ConversationId":"A","Points":4},{"ConversationId":"B","Points":6}]`。旧 `conversationId` / `corpusPoints` 单段入口继续支持，不得混用两种格式。
- `PreviewTraining` 统一提供整批的能力、占格、费用、计算量、预计耗时；`StartConversationsTraining` 一次性提交整批投入。
- `TrainingSession.GetConversationCorpus` 提供累计与剩余点数/各能力分数。
- `PreviewCorpus` 返回投入的原始能力构成；`PreviewTrainingAbilities` 包含配方和策略倍率。
- 原始语料记录不可变，训练作业保存实际扣除量；读档验证总扣除不超过来源总量。旧整条语料消耗存档继续按全额扣除解释。
- 固定投入区域和滑条保存于 `CoreGameplay` 场景的 `TrainingWorkspaceView` 下。通过场景对象调整位置，不在运行时重建固定布局。
