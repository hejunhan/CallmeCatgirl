# 可复用交接与报告模板

## 候选交接

- 项目/平台/构建路径或 URL：
- commit/build/deployment 标识：
- 需求版本与本轮变更：
- 验收目标（玩家能完成的行为）：
- 允许操作、运行环境、测试存档与隔离方式：
- 重点风险/明确不测范围/已知问题：
- 开发自测摘要（不能代替实际 QA）：
- 时间预算与制作人待判断点：

## 缺陷单

- ID、短标题、发现版本：
- 状态：新建 / 开发中 / 待复核 / 已修复 / 需求变化 / 未能复现 / 阻塞
- 严重度 S0–S3；建议优先级与玩家影响：
- 环境：平台、引擎/浏览器、视口/缩放、初始存档与输入方式
- 前置条件：
- 最短步骤：1. … 2. … 3. …
- 预期结果及需求来源：
- 实际观察（不夹杂根因猜测）：
- 首次发生及复现次数/尝试次数：
- 证据：录像时间点/截图/日志；若只能静态推断则明确标注
- 可能原因（可选、标为假设）：
- 可用绕行方式及代价：
- 修复版本与定向复核结果：

## 每轮结果

先用两句话交代玩家现在可完成什么、还被什么阻断。

- 本轮候选、测试时长、实际环境：
- 结论：通过本轮已测范围 / 有缺陷 / 阻塞 / 待制作人判断
- 已验证旅程与对应证据：
- 缺陷列表：ID、严重度、玩家影响、复现入口
- 已修复项复核：原复现路径结果、邻接路径结果、新候选标识
- 未覆盖项与原因（未测不算通过）：
- 需求变化/旧用例失效（如有）：
- 制作人手感审阅：存档/入口、短录像、1–3 个具体问题
- 下一步建议：修哪一个问题最能提高完成度；无需新构建时不继续重复检查
