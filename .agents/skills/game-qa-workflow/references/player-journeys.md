# 按风险选用的玩家旅程

本清单是菜单，不是每轮全量任务。按本轮 diff 选择；各条的实际预期以当前获批需求为准，Unity/Web 的已知语义差异须单列，不能偷偷对齐。

## Unity 编辑器可维护性与运行一致性

在同一候选、同一初始数据和参考分辨率下比较编辑态、Play 和实际 Player（最后一项仅在有构建及操作权限时）。静态 UI 容器、关键组件和可调属性应该有明确可检查的 Scene/Prefab/序列化配置来源；不能仅在 Initialize/Awake 中悄悄生成另一套静态界面，令编辑器页面失真。

检查主要按钮、布局锚点、文本和层级来源；定位运行时添加组件与对象是否重复、覆盖设计者的 Inspector 配置、依赖注册顺序。允许请求列表等真正动态内容运行时生成，但模板/数据源必须可追踪，可使用明确的编辑器预览入口。不能把所有运行态对象都强行烘焙进场景，也不能为“看得见”而给全部脚本添加 ExecuteAlways。

QA 只检查；需要试改属性时由开发在独立测试副本做一处可逆调整并交验证：改动应在运行态保留，退出 Play、重开场景不丢失。记录必要的状态差异（教程动画、实时请求）而非要求逐像素恒等。检查 Prefab overrides，不擅自 Apply All/Revert All。实际点击命中与视觉位置分别判断。

## 第一条玩家闭环

新测试档 → 博士开场选项 → 获得对应语料一次 → 中央运算格展开 → 训练页筛选/悬停/拖入格子 → 开始/取消反馈 → 主页面优先训练候选 → 完成训练 → 正式请求拖入运算 → 交付 → 对话继续 → 收益。每一步询问：知道下一步吗？可点击区域是否清楚？能取消或恢复吗？无操作入口时先记录，不直接调用内部函数越过。

## 暂停与窗口

Esc 打开左侧暂停面板；设置返回恢复正确层级；嵌套对话/训练/小游戏不误恢复世界时钟，交互按当前设计保持可用。检查双击、快速开关、切出再回、窗口缩小、长选项滚动、边缘拖动与缩放。关闭上层不应同时触发下层按钮；获得焦点后不要自动走完一段被搁置的模拟时间。不要为了覆盖切屏而修改系统安全设置。

## 拖拽与 RAM 物理安装

拖动任务时按 R、移出边界、松手无效位置、失焦取消，不能丢块/复制奖励；吸附与命中符合现有规则。RAM 抓取点相对内存条固定，离鼠标越远施力越大，单边压下有另一边抬起、中间压下有主板/插槽形变，两端卡扣保留。可用慢放录像量化位移，但“弹性好不好”留制作人。开始不扣款，完成或跳过只结算一次，取消不误升级；在测试存档复核。

## 保存与恢复

在本轮改动相关状态保存并重启候选/回菜单继续；检查钱、已完成事件、训练、政策、剧情进度保持一致且不重复奖励。旧版测试档升级应保留原备份，失败清晰提示，不以默认新档覆盖。不要清空正式浏览器存储或用户存档。导出/导入仅用已授权测试副本。

## 政策与叙事

前置、互斥分支、费用、声望变化、锁定理由与实际一致；一处购买点击不重复结算。剧情文本完整可读、选项推进不误退出、返回可恢复，任务与对话绑定。重点挑受影响的一个阶段/结局；已存在的阶段档用于快速回归必须标明，不声称从新游戏自然到达。坏结局选项删除、感情线离开/留下、结局之后继续等仅在对应改动时检查。root 决定节奏/情感与跨路线统一方案。

## Web 特定

报告实际浏览器与缩放/视口；检查滚动与固定按钮、触摸或鼠标目标、遮罩与焦点恢复、存储失败反馈。DOM 测试不代表真实布局和触控测试；本轮未有设备则明确未测。不要用“浏览器不支持”掩盖未实现功能。
